# TNV-013：重载周期启动校验

2026-10-25。本补丁针对 `NP_RELOAD_INTERVAL`，叠加 Go/HTTP2 安全更新分支。尚未合并或发布。

## 根因与修复

原通用时长解析器接受零值，`ReloadInterval=0` 随后进入管理端的 `time.NewTicker`，触发 panic。较旧代码还会将负值、空字符串或无效输入静默退回默认周期，掩盖配置错误。

本次只为重载周期引入严格解析，保留启动时的错误并在 CLI 服务核心构造前返回。服务端/客户端的公共配置入口及 `NewMaster` 也检查相同状态，避免直接构造绕过入口。错误消息给出环境变量名称与正时长要求，不回显输入或 URL 凭据。管理端校验在地址解析、读取/写入状态、启动事件工作协程之前完成。

| 输入 | 当前行为 |
| --- | --- |
| 未设置 | 默认 1 小时 |
| `50ms`、`1h` 等可解析正时长 | 接受，用于证书重载与管理端维护 |
| `0`、`0s`、负时长 | 启动失败，CLI 退出 1，无 panic |
| 显式空字符串、无效格式、超出 duration 范围 | 启动失败，CLI 退出 1，不静默回退 |
| 非正的进程内 `ReloadInterval` 覆盖 | 构造检查报错；不支持运行中修改全局时长 |

通用 `GetEnvAsDuration` 的零值语义保持原样，其他“零表示无超时”的参数未改。环境配置仍在进程初始化时读取一次；改正环境后需重启进程。删除变量可恢复默认值；设置为空不等于删除变量。`help`、`version`、显式只读 `api-key --state …` 命令不启动服务，非法重载环境下仍可使用。

修复前二进制来自干净源码 `290c3f871fb7d72f43577bf6688d9b4a4cc47ccd`，即已升级依赖的上一实现；第一个零值案例触发 panic、退出 2，且已创建状态目录。脚本按预期失败，该记录保留为失败，不改写为通过。

## 兼容与边界

此前依赖无效环境值静默回退的部署现在必须修正或删除变量，否则启动会失败。默认与合法正值的调度保持原有行为，没有增加最低正周期或动态修改环境的能力。

本次不是所有 `NP_*` 参数审计，也未改变完整维护生命周期、共享全局变量运行时并发修改、连接池和管理面安全问题。公网、长期运行和跨平台运行仍需单独验收。
