## 行为与兼容影响

- `tls=2` 必须同时提供可加载且匹配的 PEM 证书/私钥。缺少参数、不可读文件、损坏 PEM、密钥不匹配时，在构造运行核心之前失败，CLI 返回 1，不启动监听器，不降级至模式 1。
- `tls=1` 生成失败返回错误，不退回明文。模式 0 不生成无用证书，模式 2 不依赖临时自签证书生成。未知 TLS 模式拒绝启动；默认仍为 0。
- 证书重载由互斥锁串行执行，成功后发布新的不可变证书指针。失败记录错误并保留上一张证书；不改变 TLS 模式。已建立连接不会因替换指针重新握手。文件加载成功不等于证书链可信、主机名匹配或未过期；这些仍由 TLS 客户端验证。
- 服务端/客户端启动和重启日志不再插入 `TunnelKey`。Logger 最终输出、CLI 错误和子进程日志转发对 URL userinfo、整个 query 和 fragment 脱敏。无效配置 URL 不再在解析错误中回显原文；管理端无效 URL 日志同样不回显原文。
- API Key 创建、载入、轮换日志不包含值。新增显式本地命令 `tunveo api-key --state /path/to/gob/tunveo.gob`，只读现有 GOB、输出 Key 后退出；不生成 Key、不启动服务、不改变文件。原有已认证轮换响应仍返回新 Key。命令依赖本地文件读取权限，其显式输出应作为秘密处理。

部署前应修复原来依靠证书失败降级的配置，并把从日志读取 API Key 的流程迁移到显式命令。现有状态/导出格式及已认证管理响应未改变。完整迁移说明见 [migration](migration.md)。

## 首轮失败与剩余范围

首轮进程安全脚本使用 `NP_RELOAD_INTERVAL=0s` 加快重载，管理端在第 19 个案例前退出 2。独立复现确认 `time.NewTicker` 非正间隔 panic，记为 TNV-013，尚未修改。该参数还控制原有维护 ticker，最终测试使用正值 50ms；初轮失败摘要与独立复现摘要保留，不计为通过。Go 重载单元测试中的零间隔仅驱动证书回调，没有运行维护 ticker。

这些测试不是完整 TLS 安全审计：初始隧道 HTTPS 仍沿用原有跳过证书验证的协议，模式 1 的信任设计未变；严格证书全传输/SNI/过期验证、公网及长时间运行待验收。URL 脱敏不保证清洗任意非 URL 文本中的秘密，也不覆盖现有管理 API 的完整实例数据、state、导出、进程参数或较旧外部子进程的任意碎片化输出。TNV-009 管理面审计、TNV-011 安全依赖升级及完整生命周期问题仍开放。

后续状态：零重载周期的服务启动校验已在 [TNV-013](reload-interval.md) 单独实施；本页首轮失败记录仍为历史证据。
