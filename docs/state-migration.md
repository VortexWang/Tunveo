# TNV-010 离线状态迁移、备份恢复与回滚

2026-10-25。PR #12 叠加 PR #11，尚未合并或发布。本轮工具和测试不操作生产状态，也不启动迁移文件中的服务。

## 已确认的兼容范围

NodePass v1.17.0（`114345043d9608e1e24e783a270cde75193e4f42`）和当前 Tunveo 都把 `map[string]*Instance` 保存为 GOB；普通实例、Meta/Peer 和计数器的导出字段保持兼容。默认路径从旧二进制目录下的 `gob/nodepass.gob` 改为新二进制目录下的 `gob/tunveo.gob`。工具不搜索或自动重命名旧文件。

本轮使用原版 Instance/Meta/Peer 声明及原样 SaveStateToPath 方法生成夹具，并以实际原版二进制验证原版状态、当前保存和备份回滚。API Key、MID、ID、别名、URL/Config、Restart、Peer/标签及超过 int64/JavaScript 精确整数范围的计数器在样本中保持一致。

JSON export/import 会生成新实例 ID，且不包含完整的管理身份；它不是这里的保身份迁移/回滚路径。GOB 的具体编码顺序可能在重新保存后变化，因此迁移副本要求字节一致，经过运行时重新保存的文件则比较全部业务字段。

## 命令契约

```sh
# 只读、完整校验；输出数量/大小/SHA-256/身份存在标志，不输出密钥或 URL
./tunveo state inspect --state /srv/nodepass/gob/nodepass.gob

# 先停止源和目标服务；三个文件名必须不同，目标与备份均不得存在
./tunveo state migrate --offline \
  --source /srv/nodepass/gob/nodepass.gob \
  --target /srv/tunveo/gob/tunveo.gob \
  --backup /srv/private-backups/before-tunveo.gob

# 回滚/恢复到一个新的部署槽位，不覆盖运行中或已有的状态
./tunveo state restore --offline \
  --source /srv/private-backups/before-tunveo.gob \
  --target /srv/nodepass-rollback/gob/nodepass.gob
```

父目录必须预先存在，并应仅允许服务管理者访问；工具不自动创建目录。例子中的路径只是部署示例，必须按实际二进制位置替换。`--offline` 是操作者对已停止服务的声明，不是跨版本进程锁或自动停服功能。

`inspect` 不创建状态、密钥或实例；迁移/恢复要求已有 API Key 和 MID，拒绝靠启动自动补身份。所有命令先校验完整 GOB、身份及当前实例/元数据配额，拒绝截断、尾随数据、超过 128 MiB 的文件、非普通文件和符号链接文件。目录路径中的已有部署链接不等于允许状态文件本身为符号链接。

迁移保留源文件，按捕获的原字节先发布备份，再发布目标；备份与目标 SHA-256 一致。恢复同样只复制到新文件，保留输入备份。每个新文件权限为 0600、属主为执行命令的用户，默认不复制原来的宽松权限或属主；请以最终服务用户执行，或在停服状态下明确调整属主。没有 --force、覆盖、自动裁剪、自动重建 ID 或修改 TLS/路径配置的选项。环境中无效的 NP_RELOAD_INTERVAL 不阻止这些离线修复命令。

## 发布与失败边界

新副本先写入同目录临时文件并 Sync，关闭后用硬链接排他发布，避免“检查不存在、随后 rename 覆盖”的窗口；不支持硬链接的文件系统会报错，不降级为可能覆盖的方案。现有文件、断开的链接和并发发布的输家均不会覆盖赢家。阶段文件通常清除，进程被直接杀死仍可能留下权限受限的临时文件，不能将其当作正式状态。

Linux 路径在发布后同步目录；正常运行时 SaveStateToPath 也补充文件 Sync 和 rename 后目录 Sync。Windows 已交叉编译验证，但目录同步语义未在该实现中提供，不宣称 Windows 运行或掉电持久性已验证。

若目标发布失败，已完成的备份保留。若文件已发布但目录 Sync 返回错误，命令会报错并提示先检查文件，不能把非零退出简单理解为“没有产生任何文件”。修复问题后使用 inspect 核对目标/备份及 SHA，再选择新的输出路径；不自动删除已发布备份来掩盖失败。

## 操作顺序

1. 记录旧二进制的版本/哈希、实际状态路径、证书/配置路径、启动参数及环境，停止旧和目标服务，保留旧部署槽位。
2. 对源 GOB 执行 inspect。旧配置超出当前 1024 实例、URL/元数据等边界时先处理兼容问题，不要期望启动时自动截断或覆盖文件。
3. 在私有目录执行 migrate，记录报告和三个文件的哈希。不要把包含管理密钥和隧道凭据的 GOB 上传到公开工单。
4. 用目标二进制启动隔离验收，先检查认证、MID/实例 ID、配置、计数器和必要的本地转发。工具不会替操作者重写证书绝对路径、外部资源或部署参数。
5. 如需回滚，停止新服务，把原备份 restore 到新的旧版槽位，再用保存的同版旧二进制和配置验证后切换。该回滚恢复备份时点；切换后新增的配置/流量不会自动合并到旧备份。

现有周期 `.backup` 是某个一致快照，不一定是停服前最后一次状态。它可作为恢复源，但应先 inspect、核对采集时点及需要保留的变更。128 MiB 上限针对读取字节；GOB 面向本机管理员拥有的文件，不是安全接收任意外部 GOB 上传的格式，也不承诺解码器全部内部内存分配受此值限制。

## 验证与复现

运行源码/普通与 race 二进制来自干净提交 `6258767fcac0ef5ee1cdea946f9792cbefea6d92`，Go 1.26.10。本地实际原版二进制来自原版 v1.17.0 的干净提交、Go 1.26.5；CI 则从该提交的 source archive 构建旧运行时，仅作隔离回环 oracle，不链接到或发布在新产品中。

22 项跨版本检查覆盖原版生成/解码、迁移/回滚字节一致、0600 权限、已有目标拒绝、无 offline 拒绝、缺失身份/无效 ID/URL/超配额/截断/尾随/超大文件拒绝、含 Restart 的纯检查不启动、当前运行保存、实际原版读取当前保存、周期备份恢复及回滚后原版认证读取。所有运行时 oracle 的 Restart 均为 false，无隧道子进程或公网访问。

原生测试另覆盖并发发布只有一个赢家、符号链接/同路径拒绝、尾随损坏零登记，以及注入“备份成功后目标发布失败”时保留精确备份。该注入验证控制流程，不冒充真实断电、磁盘满或硬件故障测试。完整 race/vet、五轮相关包 race 和 Windows 交叉编译已通过；结果及构建信息见 [evidence/tnv010](evidence/tnv010)。
