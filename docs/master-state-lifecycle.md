# TNV-009B 实例快照、导入和子进程所有权

2026-10-25。PR #11 叠加 PR #10，尚未合并或发布。本轮覆盖管理状态共享字段、导入配额及子进程回收；不等同于整个管理面安全审计或发布验收。

## 根因与状态边界

旧实现用 sync.Map 保护登记表，但表中的 *Instance、Meta.Tags、指标和进程字段仍会原地修改。真实生产 LogWriter 的 CHECK_POINT 更新、REST PATCH/GET、GOB 保存与排队事件的 JSON 编码并发时，父提交 `0e426ede46f23a3195f49ca898cf0be5005d7025` 检测到 DATA RACE；已经入队的事件也会随之后的别名修改而变化。

现在 Master.dataMu 统一拥有可变实例字段。普通 REST/MCP 控制处理器串行访问状态，将响应编码到有界私有缓冲，再在状态锁外写网络。进程等待、TCPing、系统信息采样和导入文件读取会释放状态锁；文件保存先在锁内深拷贝，再在锁外编码/落盘。这里的状态事务边界不是数据库式任意错误回滚；元数据先校验再修改，导入另有整批预检。

公开 FindInstance 返回深拷贝，修改结果不再修改登记对象；内部可变引用只能在所有权边界内使用。标签字典同样深拷贝，快照不保留 exec.Cmd、运行代际或待执行动作。SSE 入队时捕获快照，初始状态先取 ID 列表、再逐条快照和发送，避免每个订阅者同时复制整张大表。逐条快照一致，但不承诺整个初始流对应同一时刻。

保存请求合并为一个工作者和一个脏标志，避免每次 PATCH 启动一个等待文件锁的 goroutine。普通管理控制请求也会串行排队，可能增加延迟；它们仍受 TNV-009A 的 32 个准入上限和请求 context 约束。性能需在后续负载验收中量化。

## 子进程代际与回收

每次启动创建独立 childRun，保存命令、完成及最终回收信号。该代际只有一处 cmd.Wait，统一负责进程和输出管道回收；停止操作不再另调 Process.Wait，也不会在发送 SIGTERM 后立即用 context 取消强杀。旧日志和退出回调核对运行代际，不得覆盖重启后的状态或复活已删除登记项。

停止先发 SIGTERM（Windows 保持中断信号分支），正常等待 5s；到期或关闭 context 取消后强杀，再给回收最多 5s 的观察窗口。命令设置 WaitDelay 限制退出后输出管道等待。未完成 Wait 的进程仍在独立登记表中并占用子进程配额，即使实例已删除，也不会丢失跟踪。

同一实例最多一个动作工作者、一个待执行动作，新待办覆盖旧待办；当前已经开始的动作不保证被追溯撤销。周期重启遵守 Restart 标志。健康监控每轮从未收到 CHECK_POINT 的状态开始，收到首个检查点后才按间隔判断，避免把启动阶段误判为无响应。

恢复先校验全部登记项，再发布；自动启动延迟到 API 监听绑定成功之后。无效状态或超额状态在构造阶段报错，原文件不改写，也不会先启动其中一个有效前缀。绑定失败不启动恢复的实例；现有 Run 的绑定失败日志/退出状态语义未整体重设计。

关停单次执行：关闭新动作准入，结束周期循环和 SSE，等待动作/保存工作者及进程代际回收，最后持久化。调用者 context 到期时强制关闭 API 并对仍跟踪的子进程发送 Kill，返回错误；不会将未解决的工作标记为成功或宣称已完成最终持久化。内核进程等待、文件系统和外部阻塞调用并无无条件硬实时保证。

## 固定资源边界

| 项目 | 上限/策略 |
| --- | --- |
| 普通登记实例 | 1024，不计 API Key 特殊项；REST 创建、MCP 创建/导入及恢复统一校验 |
| 活跃子进程 | 64，只有实际 Wait 回收后才释放配额 |
| 启动尝试 | 每个固定一分钟窗口 128 次；窗口边界允许突发，不是滚动窗口或均匀速率 |
| 导入文件/批次 | 普通文件、最多 8 MiB、每批最多 256 条；整批解析、身份/URL/元数据及剩余容量校验后才发布和安排启动 |
| 实例元数据 | URL 最多 8192 字节；别名/Peer/标签键值沿用 256 字节，每实例最多 128 个标签 |
| 通知队列 | 固定 256 个快照，满时丢弃；不再借用通用 NP_SEMAPHORE_LIMIT 的默认 65536 槽位 |
| 普通响应缓冲 | 16 MiB，超额返回 507；JSON 编码器临时内存仍随有界登记规模增长 |
| 后台工作 | 保存合并、每实例动作合并；不是任意用户回调都可强制中断的承诺 |

达到子进程/启动配额的实例进入 error，等待后续合法重试；不会自动提高上限。大规模滚动重启和既有超额状态需要提前规划。HTTP 1 MiB 请求体上限仍适用；MCP 本地文件导入另受上述文件边界限制。

## 验证与来源

普通/race 二进制均从干净运行提交 `388190ba040eff45e81cc4079714d3d57ece8d3d`、Go 1.26.10 构建。最终夹具提交 `1aa2fefa6a3720f78d5f5d2a20211935c98278e6` 仅补测试对异步保存/动作的清理等待，不修改运行源码。

原生前后脚本把相同模板复制到 git archive，仅切换测试预期。包含实际生产 LogWriter、REST 修改/读取、GOB 编码和排队事件编码，无生产源码插桩、无真实子进程。旧版要求检测到 DATA RACE 和快照缺陷，新版要求成功且不出现竞争；完整输出、模板/驱动哈希保留。

真实 race 进程回归启动 Master 和两个回环 single-mode 子进程，执行 120 次元数据修改与 120 次读取、周期备份、重启、8 次合并停止、重新启动、删除、父进程关停及绑定失败不自动启动。启动 PID 与唯一 cmd.Wait 的完成记录对应；当前执行环境不提供子进程 /proc 查询，因此不把它当作独立内核观察。原生测试另外运行真实 shell 子进程，验证并发 Stop 后 ProcessState.Success、唯一等待者及配额归零。进程回归不发送隧道业务流，CHECK_POINT 字段竞争由上述原生并发夹具覆盖。

额外回归覆盖旧代际输出隔离、动作合并、活跃配额与启动尝试拒绝、超额/无效导入零副作用、深拷贝字典、关停幂等/关闭后拒绝动作、恢复失败保留原文件，以及按原字段解码 GOB 和大于 int64 上限计数器的精确保存。这是兼容性抽样，完整迁移与回滚仍属 TNV-010。
