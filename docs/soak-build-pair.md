# 普通与race构建配对RSS短测

接PR31。原完整窗口RSS增量71.00390625MiB、超64MiB 7.00390625MiB，20/36负载点超限；原失败不改写。本轮检验同一源码普通构建是否也触发原资源门槛，作为后续排查优先级依据。

同一CI job、同一主机，编译ordinary和race二进制，要求干净Git来源与相同revision；顺序ordinary→race→race→ordinary，每次为独立新进程。每类两次是最低限度重复，不能建立统计因果或证明长期稳定。构建只差-race，均trimpath；记录主机、Go版本、构建信息及二进制哈希。

参数统一：H2 transport3/mode1、TLS默认1、pool16:64、2worker10QPS、12秒预热、180秒measured、5秒采样，再120秒停载重复GC及显式Go回收。本轮不挂BPF、不设置外部观察者ACK，也不直接与PR31的BPF窗口作因果对比；所有结果作为独立新实验。原生探针与verify_soak.py不修改，RSS64MiB及原失败退出规则保持。每次原验证失败后仍执行下一次，最终任一次失败令配对任务失败，完整上传全部可用原件。

新增soak_build_pair.py从每份report只读列出全部ACTIVE资源的基线/峰值/增量/超限点，全部RETURN检查及首末四分位中位数趋势，记录预热RSS序列。趋势的正式阈值在pilot中仅展示，不假装已执行正式验收。原RETURN不含RSS，RSS停载值不能抵消负载峰值。数据格式/完整性仍由原验证器判定；汇总不替代原资格规则。即使RSS先失败，也单独审计业务事件及日志，避免首错遮蔽后续检查。

工作流总40分钟；构建和测试8、四次实验24、上传2分钟，预留6分钟用于准备/清理。每次原runner仍有原生窗口加120秒的等待边界，全部运行都为pilot，qualifies_24h始终false。

本地106项测试通过（新增2项）；只读汇总用PR31原ZIP回放，精确复现74452992B增长和20个超限点。真实CI尚待完成，不能用本地或旧race窗口代替。

判定：普通/race分别保留各次原结果。普通通过可建立该构建的短测证据，不能关闭race历史失败；普通也失败则优先检查业务分配、堆页驻留及生命周期。重复结果不一致需继续复现，不能挑选成功样本。此后再按重复负载/停载及具体对象入口观测区分首次扩张、复用和持续累积。预热稳定性先只报告，禁止为了通过事后抬高基线。保持草稿、未合并/发布，不启动24h。
