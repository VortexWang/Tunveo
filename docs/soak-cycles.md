# 同进程三轮负载/停载诊断

接PR32：同机ABBA中普通构建两次RSS增长10.6171875/8.65234375MiB通过，race两次70.08203125/68.61328125MiB失败，原64MiB门槛与历史结果保留。本轮检查后续周期的峰值、低水位及虚拟映射形态是否继续增长，不把不同新进程间的差异当作同进程复用证据。

给测试探针增加显式 --diagnostic-cycles=3；默认1保持单轮路径。三轮模式仅允许180秒负载、12秒预热、5秒采样、120秒停载及显式Go回收，禁止观察者ACK和goroutine栈诊断。每轮重新创建端点/fixture并完成原关闭流程，业务失败停止该进程后续轮次；成功的轮次保留原业务/日志/资源报告。三轮始终在一个原生进程中运行，报告cycle index与总轮数，验证器要求同一PID及实际启动子进程PID一致。原生产引擎、依赖与verify_soak.py未修改。

Python先运行ordinary三轮，再运行race三轮；同机、相同干净revision，两份构建仅差-race。每轮保留原validate_report的本地预热口径和错误；另外用第一轮后半预热的最大值冻结所有ACTIVE资源基线，三轮负载点全部必须满足原allowance（RSS64MiB），后续预热不得重置固定基线。任一轮原检查或跨轮固定检查失败，整项失败，仍保存已完成结果。全部为诊断，qualifies_24h=false。

逐轮列出：固定基线/峰值/全部超限点、原局部汇总、首个/末次停载GC RSS、观察期间最低GC RSS、显式Go回收后RSS；最后两个指标不能抵消负载峰值。停载采用重复强制GC及Go回收，是诊断条件，不冒充自然空闲。

仅三轮模式在checkpoint另存完整压缩smaps，索引包含PID、轮次、负载/停载点数量、原文哈希及同一实验起点的单调时钟读取区间。检查索引顺序和原文哈希。资源采样与smaps读取非原子；额外快照会带来诊断开销。本轮没有系统调用台账/映射代次，观察到相同地址与边界不能认定同一对象或代次复用，不能证明所有race家族是缓存。第一步仅建立同进程时间序列，具体对象归属仍需独立入口可观测性与控制实验。

本地112项Python测试通过（新增4项），覆盖后续预热升高不能掩盖固定基线超限、PID变化、缺轮及缺失Go回收拒绝。新增Go smaps索引回归；本地无Go工具链，Go编译和原生命周期回归交专项CI执行，尚无真实多轮结果。测试探针默认单轮回归也由CI执行。

CI总60分钟：测试/编译8分钟、两个三轮进程46分钟、上传3分钟，留3分钟准备清理。每进程等待上限3×432秒，超时终止/回收并判失败。编译前检查源码干净，元数据及实验文件在编译后产生。普通三轮与race三轮顺序固定、每类仅一个进程样本，不能建立因果或长期有界结论。

判定：初始扩张后近似平台、逐轮上升或不一致均只作为后续控制实验方向；不得挑选低值、重置基线、放宽64MiB或改GORACE/GODEBUG来改写失败。保持草稿、未合并、未发布，24小时验收未启动。
